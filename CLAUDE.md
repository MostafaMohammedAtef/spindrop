# Spindrop project guide

## What this project is

Spindrop is a responsive vinyl-record storefront and artist landing site. It is a client-side React application built with TypeScript and Vite. The experience includes a marketing homepage, a discoverable record catalog, artist collections, a persistent demo cart, country/currency selection, and demo sign-in/account creation.

This repository does not currently provide a production commerce or authentication backend. Do not describe the demo flows as real checkout, payment processing, or secure authentication.

## Stack and commands

- React 19, TypeScript, React Router 7, Vite 8
- Tailwind CSS 4 through the Vite plugin, with custom theme and animation CSS
- `lucide-react` for interface icons
- `oxlint` for linting
- Node.js 20.19+ or 22.12+ and npm

```sh
npm install
npm run dev       # Local development server
npm run build     # TypeScript project checks and production Vite build
npm run lint      # Oxlint
npm run preview   # Serve the production build locally
npm run convert:vinyls  # Run scripts/convert-vinyls.mjs
```

There is no test script configured in `package.json`.

## Routes and page composition

`src/main.tsx` mounts the app inside `BrowserRouter`. `src/App.tsx` provides the shared cart and pricing contexts, the header, and route selection:

- `/` and any unmatched path show the marketing homepage.
- `/discover` shows the record catalog with price sorting, pagination, currency selection, and add-to-cart actions.
- `/artists/:artistSlug` shows records by the selected artist. Slugs are generated by `artistSlug` in `src/data/records.ts`.
- `/cart` shows cart contents and an estimated subtotal; there is no checkout flow.
- `/login` and `/sign-in` show the same demo sign-in page.
- `/create-account` creates a demo account.

The homepage sections are composed in `App.tsx`: `WhyHero`, `SplitCards`, `Services`, `RetailSupport`, `Community`, `ArtistMarquee`, `ArtistTestimonials`, `VinylStudio`, and `Footer`.

## Code map

- `src/App.tsx`: app shell, providers, loading behavior, and routes.
- `src/components/`: route pages and reusable page sections. Keep page/section UI in this area and use the existing shared components where appropriate.
- `src/data/records.ts`: storefront record catalog, record type, local artwork imports, prices, and artist-slug helper. This is the catalog currently consumed by Discover, Artist, and Cart pages.
- `src/data/artists.ts`: artist links used by the marketing site.
- `src/lib/CartContext.tsx`: cart state and localStorage persistence under `spindrop.cart`.
- `src/lib/PricingContext.tsx`: country selection, estimated currency conversion, and price formatting.
- `src/lib/demoAuth.ts`: browser-local demo account/session helpers.
- `src/index.css`: Tailwind import, color palette, font tokens, animations, and loading-screen styles.
- `src/App.css`: legacy starter styles; check whether a rule is still used before changing it.
- `src/assets/` and `public/`: imported source images and public/static branding assets.
- `backend/vinyl-images/`: vinyl artwork files imported directly by `src/data/records.ts`; despite the folder name, this is not a running API server.
- `backend/vinyls.json`: accompanying vinyl data file; check its current contents before relying on it as the app's catalog.
- `scripts/convert-vinyls.mjs`: vinyl image/data conversion utility.

## Important behavior and limitations

- Cart state stores record IDs and quantities in browser localStorage. Record names, artwork, and prices come from the in-code catalog in `src/data/records.ts`.
- Market selection is saved under `spindrop.market-country`. The app requests reference exchange rates from Frankfurter; if unavailable, prices fall back to USD. Prices are illustrative/demo prices.
- Sign-up and sign-in only use browser localStorage (`spindrop.demo.accounts` and `spindrop.demo.session`). The demo helper stores passwords in the browser and must not be used as a model for production authentication.
- Accounts, cart, and country selection are device/browser-local; there is no server synchronization.
- The cart has item removal and estimated subtotal, but no quantity editor, stock validation, order submission, shipping, or payment integration.

## UI and implementation conventions

- Use functional React components and TypeScript. Keep types explicit and avoid weakening type checks.
- Use React Router `Link` for internal navigation and the existing cart/pricing contexts rather than duplicating their state.
- Match the established Spindrop visual style: bold typography, black borders, bright palette colors, vinyl/artist imagery, and responsive Tailwind utility classes.
- Theme colors such as `bg-palette-11`, `bg-brand-yellow`, and font tokens are defined in `src/index.css` under Tailwind's `@theme`. Add or reuse theme tokens there rather than introducing arbitrary repeated colors.
- Keep designs responsive and accessible: use semantic elements, descriptive image text where meaningful, button labels, and visible keyboard focus states.
- Local image files should generally be imported from `src/assets/` or `backend/vinyl-images/`; files in `public/` are addressed by public URL paths.
- Preserve the demo-only scope unless a task explicitly asks to add a backend or real integrations. Update this guide when architecture or commands materially change.
